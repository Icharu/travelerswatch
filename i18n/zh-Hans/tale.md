# 旅人之表

*为本项目所写的原创改写故事。*

一位旅人动身穿越一座被浓雾整个吞没的山谷。他看不见道路，于是信任身上唯一不必靠眼睛的东西：他的怀表。他用小时来估算这段旅程——走到正午，在石桥处转向东方，黄昏时抵达城镇。

在表所说的正午，他停下脚步，用右手食指按下表冠，读着指针。十二点。他转向东方，继续前行。过了一阵子，他又看了一次——表上显示差十分十二点。他皱起眉头，以为自己看错了，就一直走到表又指向十二点，再次转向东方。

他不知道这块表坏了。每当他在正午按下表冠，指针就倒退十分钟。所以每次看表，他都在重走一段已经走过的路，却坚信自己在前进。浓雾遮住了他一再经过的石桥。到了傍晚，他筋疲力尽，离城镇却一点也没有更近，也说不出自己把这一天丢在了哪里。

城墙上，一位守望者整夜坚守岗位。城下的旅人向他喊出那个古老的问题——*"守望的啊，夜里如何？"*——而他只回答自己真正看得见的事：道路通向哪里，离天亮还有多远。他不猜测，也不奉承。道路改变时，他会说出来，也会说明原因。

旅人的麻烦不是雾。雾很平常，每条长路都会有一些。他的麻烦在于一个无法信任的参照：偏偏在他最需要它的时候被拿出来查看，又毫无预警地倒退——而且没有人守望着告诉他：那座桥，你之前已经见过了。

如果那天夜里他走到了城墙下，喊出那个古老的问题，守望者就会告诉他自己真正看见的事：他一再经过的桥其实是同一座，而他的表正在倒退。旅人便会打开表壳，把表修好。他不会凭着表自己的说法去修，因为出错的正是那块表。而如果旅人不在那里发问，守望者也永远不会叫他修表。两人之中，谁也无法独自修好那块表。

## 为什么这是一个 skill

借助语言模型推进的长期项目，也会以非常相似的方式漂移。早期假设逐渐固化，部分对话在摘要中丢失，而模型一旦走错一步，就会不断回到那条错路，同时每一个单独的步骤看起来都像在前进。The Traveler's Watch 给项目两样旅人所缺少的东西：

| 在故事中 | 在 skill 中 |
|---|---|
| 发问、做决定并修好表的旅人 | **你，项目经理**——由你设定航向，并确认每一次变更 |
| 一块值得信赖的表 | `.watch/WATCH.md` 中的**航向**——写成文字、提交到版本库，不会因上下文丢失而倒退 |
| 守望者诚实的汇报 | **守望者 hook**——每次提示时，如果工作偏离就用一行提醒 |
| 有意转向东方 | **`/fixwatch`**——经过选择、由项目经理确认并记录的方向调整 |
| 出发前先认识道路 | **`/checkwatch`**——上路前先商定标准、上下文、约束、问题和工具 |
| 从城门回望 | **项目后评审**——航行日志所呈现的整段旅程 |

任何一方都无法单独运作。守望者只能回答在场发问的旅人，而旅人也无法信任一块没有人检查的表。这就是为什么 TTW 是一种在模型与人*之间*使用的方法，而绝不是替你走完道路的工具。

*"守望的啊，夜里如何？"*一句出自以赛亚书 21:11（和合本；属于公有领域）。
