# 旅人之錶

*為本專案所寫的原創改寫故事。*

一位旅人動身穿越一座被濃霧整個吞沒的山谷。他看不見道路，於是信任身上唯一不必靠眼睛的東西：他的懷錶。他以小時來估算這段旅程——走到正午，在石橋處轉向東方，黃昏時抵達城鎮。

在錶所說的正午，他停下腳步，用右手食指按下錶冠，讀著指針。十二點。他轉向東方，繼續前行。過了一陣子，他再看一次——錶上顯示差十分十二點。他皺起眉頭，以為自己看錯了，便一直走到錶又指向十二點，再次轉向東方。

他不知道這只錶壞了。每當他在正午按下錶冠，指針就倒退十分鐘。所以每次看錶，他都在重走一段已經走過的路，卻深信自己正在前進。濃霧遮住了他一再經過的石橋。到了傍晚，他筋疲力盡，離城鎮卻一點也沒有更近，也說不出自己把這一天丟在了哪裡。

城牆上，一位守望者整夜堅守崗位。城下的旅人向他喊出那個古老的問題——*「守望的啊，夜裡如何？」*——而他只回答自己真正看得見的事：道路通往何處，離天亮還有多遠。他不猜測，也不奉承。道路改變時，他會說出來，也會說明原因。

旅人的麻煩不是霧。霧很平常，每條長路都會有一些。他的麻煩在於一個無法信任的參照：偏偏在他最需要它的時刻被拿出來查看，又在毫無預警下倒退——而且沒有人守望著告訴他：那座橋，你之前已經見過了。

如果那天夜裡他走到了城牆下，喊出那個古老的問題，守望者就會告訴他自己真正看見的事：他一再經過的橋其實是同一座，而他的錶正在倒退。旅人便會打開錶殼，把錶修好。他不會憑著錶自己的說法去修，因為出錯的正是那只錶。而如果旅人不在那裡發問，守望者也永遠不會叫他修錶。兩人之中，誰也無法獨自修好那只錶。

## 為什麼這是一個 skill

借助語言模型推進的長期專案，也會以非常相似的方式偏移。早期的假設逐漸固化，部分對話在摘要中流失，而模型一旦走錯一步，就會不斷回到那條錯路，同時每一個單獨的步驟看起來都像在前進。The Traveler's Watch 給專案兩樣旅人所缺少的東西：

| 在故事中 | 在 skill 中 |
|---|---|
| 發問、做決定並修好錶的旅人 | **你，專案經理**——由你設定航向，並確認每一次變更 |
| 一只值得信賴的錶 | `.watch/WATCH.md` 中的**航向**——寫成文字、提交到版本庫，不會因脈絡流失而倒退 |
| 守望者誠實的回報 | **守望者 hook**——每次提示時，若工作偏移就用一行提醒 |
| 刻意轉向東方 | **`/fixwatch`**——經過選擇、由專案經理確認並記錄的方向調整 |
| 出發前先認識道路 | **`/checkwatch`**——在上路前先議定標準、脈絡、限制、問題與工具 |
| 從城門回望 | **專案後檢討**——航行日誌所呈現的整趟旅程 |

任何一方都無法單獨運作。守望者只能回答在場發問的旅人，而旅人也無法信任一只沒有人檢查的錶。這就是為什麼 TTW 是一種在模型與人*之間*使用的方法，而絕不是替你走完道路的工具。

*「守望的啊，夜裡如何？」*一句出自以賽亞書 21:11（和合本；屬公有領域）。
