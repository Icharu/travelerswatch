# 旅人の時計

*このプロジェクトのために書かれた、オリジナルの再話。*

ある旅人が、霧にすっかり呑み込まれた谷を越えようと旅立った。道は見えなかったので、彼は持ち物のなかで唯一、目に頼らずにすむものを信じた。懐中時計である。彼は旅の行程を時間で見積もっていた。正午まで歩き、石の橋で東に曲がり、日暮れまでに町に着く。

時計が正午と告げたところで、彼は立ち止まり、右手の人差し指で竜頭を押して針を読んだ。十二時。彼は東に曲がり、歩いた。しばらくしてもう一度見ると、時計は十二時十分前を指していた。彼は眉をひそめ、読み違えたのだろうと思い、時計がふたたび十二時を指すまで歩き続けた。そしてまた東に曲がった。

彼は時計が壊れていることを知らなかった。正午に竜頭を押すたびに、針は十分戻ってしまうのだ。だから時計を見るたびに、彼はすでに歩いた道をまた歩き直していた。前に進んでいると、すっかり信じたまま。霧は、彼が何度も通り過ぎる石の橋を隠していた。夕方には疲れ果て、町には少しも近づいておらず、どこで一日を失ったのかもわからなかった。

町の城壁の上では、ひとりの見張り番が夜通し持ち場を守っていた。下を通る旅人たちは、古くからの問いを彼に投げかけた。*「見張り番よ、夜はどうか」*。彼は、自分に実際に見えることだけを答えた。道がどこへ続くのか、夜明けまであとどれくらいか。当て推量もせず、お世辞も言わなかった。道が変われば、変わったと告げ、その理由も告げた。

旅人を困らせていたのは霧ではなかった。霧はよくあることで、長い道にはどこかに霧がある。困ったのは、信頼できない基準だった。いちばん頼りたいときに限って見返され、知らせもなく巻き戻る基準。そして、その橋はもう見たはずだと教えてくれる見張りが、誰もいなかったことだった。

もしその夜、彼が城壁までたどり着き、古くからの問いを投げかけていたなら、見張り番は自分に実際に見えることを告げただろう。彼が何度も通り過ぎていた橋はひとつきりで、彼の時計は遅れていく、と。旅人は蓋を開けて、時計を直しただろう。時計の言うことを頼りに直したのではない。間違っていたのは、ほかならぬ時計だったのだから。そして旅人がそこにいて問いかけなければ、見張り番が時計を直せと言うこともなかっただろう。どちらも、ひとりでは時計を直せなかった。

## なぜこれがスキルなのか

言語モデルと進める長期プロジェクトも、よく似た形でずれていきます。初期の思い込みが固まり、会話の一部は要約の中で失われ、一度道を誤ったモデルは、一歩一歩は前進に見えながら何度もその誤りに戻ってしまいます。The Traveler's Watch は、旅人に欠けていた二つのものをプロジェクトに与えます。

| 物語の中では | スキルでは |
|---|---|
| 問いかけ、決め、時計を直す旅人 | **あなた、つまりプロジェクトマネージャー**：針路を決め、すべての変更を確認します |
| 信頼できる時計 | `.watch/WATCH.md` の**針路**：書き留められ、コミットされ、コンテキストが失われても巻き戻りません |
| 見張り番の正直な報告 | **見張り番 hook**：プロンプトのたびに、作業がずれていれば一行で知らせます |
| 意図して東に曲がること | **`/fixwatch`**：選ばれ、プロジェクトマネージャーが確認し、記録される針路変更 |
| 出発前に道を知っておくこと | **`/checkwatch`**：歩き出す前に、基準・コンテキスト・制約・課題・ツールを合意します |
| 町の門から振り返ること | **プロジェクト事後レビュー**：航海日誌が旅全体について示すもの |

どちらの側も、ひとりでは成り立ちません。見張り番は、そこにいて問いかける旅人にしか答えられず、旅人は誰も確かめない時計を信頼できません。だからこそ TTW は、モデルと人の*あいだ*で使う方法であり、あなたの代わりに道を歩くツールでは決してないのです。

*「見張り番よ、夜はどうか」*という一句は、イザヤ書 21:11 からのものです（原文はパブリックドメイン。訳文は本翻訳によるもの）。
